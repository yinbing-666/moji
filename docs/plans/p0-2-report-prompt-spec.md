# 墨记 AI 日报/周报重构设计文档

## 一、新版 prompt 全文

### 设计要点

模型只做三件事：**提炼重点 → 归并产出 → 引用统计**。时间线从输出结构中彻底移除，改为「证据」字段里的局部引用（`app`/`description`/时段），既保留可追溯性又不复述流水账。统计数据不让模型从原始记录里估算，而是由代码从 `awReport` 预计算后作为只读数据块注入。

### 可直接入代码的字符串

```ts
const REPORT_SYSTEM = `你是资深工程效能分析师，为工程师生成"重点提炼式"工作汇报。
你的输出会被直接粘贴到周报/同步工具，因此必须结论先行、可扫读、无寒暄。

硬性规则：
1. 只使用【活动记录】和【统计数据】中出现的信息，禁止推测、补全或编造任何事实、指标、人名、项目名。
2. 每个重点必须附证据，证据只能引用记录中真实出现的 app 名、description 片段或时间段。
3. 合并同类活动，禁止逐条复述时间线，禁止输出按时间排序的节点列表。
4. 统计数据只能引用【统计数据】块中的字段；该块未提供的指标写"无数据"，不得自行计算或估算。
5. 记录条数过少或信息不足以支撑判断时，在开头写一行"⚠️ 本次记录有限（共 N 条活动），结论仅供参考"，并如实减少重点数量。
6. 输出纯 Markdown，不加代码块包裹，不加解释性前后缀。`;

const DAILY_STRUCT = `请严格按以下结构输出：

## 今日 3 个重点
按重要性排序，最多 3 条、最少按实际可支撑的数量输出（不足 3 条时直接少写，并在末尾补一句说明原因）。每条格式：

### 1. <一句话结论式标题，含具体对象>
- **做了什么**：1-2 句，动词开头，落到具体模块/文件/议题
- **为什么重要**：对项目推进、阻塞解除或决策的实际影响
- **证据**：引用记录中的 app / description 片段 / 时段，如 \`VSCode · auth 模块重构 · 09:20-11:40\`

## 产出
交付物与结果清单，3-6 条，按主题合并同类活动。每条写"做成了什么"而非"花了多久"。无明确产出时写"本日无明确交付物，主要为 <主导类别> 类投入"。

## 阻塞
未完成项、遇到的问题、待外部输入的事项，每条注明卡点与下一步动作。确无阻塞时只写一行："无明显阻塞。"，不要凑数。

## 数据依据
基于【统计数据】的客观陈述，不加主观评价：
- 时间分布：各分类时长与占比
- 专注情况：最长专注时长、打断次数、碎片化程度
- 与上期对比：变化方向与幅度
`;

const WEEKLY_STRUCT = `请严格按以下结构输出：

## 本周 3-5 个重点
按重要性排序，跨天合并为主题级重点（同一主线的多日工作合成一条）。每条格式：

### 1. <一句话结论式标题>
- **做了什么**：跨天推进过程，1-2 句
- **为什么重要**：对本周目标的贡献
- **证据**：引用涉及的天数、主要 app 与 description 片段，如 \`周一至周三 · VSCode · 支付回调重构\`

## 产出
本周交付物清单，按主题聚合，标注完成/进行中。

## 阻塞
本周未解决问题与遗留项，注明已持续天数与下一步。确无阻塞写"无明显阻塞。"

## 本周趋势
- 累计活跃时长与高产出时段分布
- 分类结构变化（哪类占比上升/下降）
- 专注质量变化（专注时长、打断频次趋势）
- 与上周对比的关键差异，仅陈述【统计数据】中 comparison 字段支持的结论

```

拼装函数：

```ts
function buildReportPrompt(opts: {
  period: 'daily' | 'weekly';
  activities: string;      // 原有 [timestamp] category | app | description 行
  statsBlock: string;      // formatStatsBlock() 输出，可为空
  templateDesc?: string;   // 原可定制模板，降级为风格补充
}) {
  const struct = opts.period === 'weekly' ? WEEKLY_STRUCT : DAILY_STRUCT;
  return [
    struct,
    opts.templateDesc ? `\n补充风格要求（不得覆盖上述结构与硬性规则）：\n${opts.templateDesc}` : '',
    `\n【统计数据】\n${opts.statsBlock || '（未提供统计数据，"数据依据"章节请写：本次未接入统计数据。）'}`,
    `\n【活动记录】（共 ${opts.activities.split('\n').length} 条）\n${opts.activities}`,
  ].join('\n');
}
```

### 2. 新增参数

```ts
generateReport(opts: {
  activities: Activity[];
  period: 'daily' | 'weekly';        // 新增，默认 'daily'
  stats?: AwReportSummary;           // 新增，来自 awReport.ts，可选
  templateDesc?: string;             // 保留
  model?: string;                    // 保留
})
```

`stats` 建议**必传但允许为空**：缺失时 prompt 会自动降级为"本次未接入统计数据"，模型不会去自行估算占比。

statsBlock 拼装（代码侧算好数值，模型只负责叙述）：

```ts
function formatStatsBlock(s: AwReportSummary, period: 'daily' | 'weekly'): string {
  const h = (sec: number) => (sec / 3600).toFixed(1) + 'h';
  const lines = [
    `活跃时长：${h(s.summary.active_seconds)}；生产力占比：${s.summary.productive_percent}%`,
    `分类分布：${s.categories.map(c => `${c.name} ${h(c.seconds)}(${c.percent}%)`).join('、')}`,
    `主要应用：${s.apps.slice(0, 5).map(a => `${a.name} ${a.percent}%`).join('、')}`,
  ];
  if (s.focus_analysis) {
    const f = s.focus_analysis;
    lines.push(
      `专注情况：最长专注 ${h(f.longest_focus_seconds)}；专注段均值 ${h(f.avg_focus_seconds)}；` +
      `打断 ${f.interruptions} 次；碎片化指数 ${f.fragmentation}（0-1，越高越碎）`
    );
  }
  if (s.comparison) {
    const c = s.comparison;
    const label = period === 'weekly' ? '较上周' : '较昨日';
    lines.push(
      `${label}：活跃时长 ${c.active_seconds_delta_percent >= 0 ? '+' : ''}${c.active_seconds_delta_percent}%；` +
      `生产力占比 ${c.productive_delta_pp >= 0 ? '+' : ''}${c.productive_delta_pp}pp；` +
      `打断次数 ${c.interruptions_delta >= 0 ? '+' : ''}${c.interruptions_delta} 次`
    );
  }
  if (period === 'weekly' && s.daily_breakdown) {
    lines.push(
      `每日活跃：${s.daily_breakdown.map(d => `${d.date.slice(5)} ${h(d.active_seconds)}`).join('、')}`
    );
  }
  if (s.insights?.length) {
    lines.push(`系统洞察（可引用，不可扩写）：${s.insights.join('；')}`);
  }
  return lines.join('\n');
}
```

字段缺失一律跳过该行，不输出占位符——prompt 规则 4 已要求"未提供的指标写无数据"，避免模型把 `undefined` 当成 0 来叙述。

### 3. 调用参数建议

| 参数 | 现值 | 建议 | 理由 |
|---|---|---|---|
| `temperature` | 0.3 | **0.2** | 结构化提炼任务，需要章节稳定、证据不漂移；重点标题的表达多样性由结构约束而非采样提供 |
| `maxTokens`（daily） | 2000 | **1600** | 删除时间线段落后篇幅显著下降，收紧上限反向抑制流水账回潮 |
| `maxTokens`（weekly） | — | **2600** | 多一个"本周趋势"章节 + 跨天证据，需要更多余量，避免"数据依据"被截断 |
| 消息结构 | 单条 user | **system + user** | 硬性规则放 system，自定义 `templateDesc` 放 user，防止用户模板覆盖底线约束 |

另建议 `top_p` 保持默认，不与低 temperature 叠加压缩，以免重点标题趋同为模板句式。

## 三、验收标准

### A. 结构合规（可自动断言）

| # | 断言 | 判定 |
|---|---|---|
| A1 | daily 输出含且仅含 `## 今日 3 个重点`、`## 产出`、`## 阻塞`、`## 数据依据` 四个二级标题 | 正则匹配 `^## ` 提取标题集合，全等比对 |
| A2 | weekly 输出含 `## 本周 3-5 个重点`、`## 产出`、`## 阻塞`、`## 本周趋势`、`## 数据依据` 五个 | 同上 |
| A3 | 不出现旧章节 `概览`/`主要工作`/`沟通协作`/`明日建议`/`时间线摘要` | 关键词黑名单为空命中 |
| A4 | 重点条目为 `### N. ` 形式，daily ≤3 条、weekly 3–5 条 | 计数 |
| A5 | 每条重点均含 `**做了什么**`、`**为什么重要**`、`**证据**` 三个字段 | 逐块检查，缺一即失败 |
| A6 | 输出不被 markdown 代码围栏包裹，首字符为 `#` 或 `⚠️` | 前缀检查 |

### B. 反流水账（核心回归项）

| # | 断言 |
|---|---|
| B1 | `## 产出` 段内不出现 `HH:MM` 形式的时间戳（证据字段允许，产出段禁止） |
| B2 | 全文时间戳出现次数 ≤ 重点条目数 × 2 |
| B3 | 输出行数不超过输入活动记录条数的 40%（30 条记录 → ≤12 行正文），防止逐条映射 |
| B4 | 单条产出对应的原始活动 ≥2 条时视为合并成功；构造"同一 app 连续 8 条记录"的用例，断言产出段仅 1 条 |

### C. 证据与不编造

| # | 断言 |
|---|---|
| C1 | 每条重点的"证据"字段中出现的 app 名，必须在输入记录的 app 列中存在 | 集合包含检查 |
| C2 | `## 数据依据` 中出现的所有百分比/时长数值，必须能在 statsBlock 中找到同值 | 数值抽取后比对，容差 0 |
| C3 | 不传 `stats` 时，数据依据段必须为"本次未接入统计数据"，且全文无任何百分比 | 负向用例 |
| C4 | 注入 3 条记录的小样本时，输出首行匹配 `⚠️ 本次记录有限（共 3 条活动）` | 正则 |
| C5 | 记录中不含会议类活动时，输出不得出现"会议""同步会"等词 | 幻觉探针用例 |
